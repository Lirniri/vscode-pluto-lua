# Pluto & Lua: Mini-IDE

*Мини-IDE для [Pluto](https://plutolang.github.io/) и Lua в Visual Studio Code: подсветка синтаксиса, автодополнение, подсказки, помощники при наборе, диагностика, проверка синтаксиса Lua и панель настроек.*

[English version](README.md)

## Установка и быстрый старт

1. Скачайте `pluto-lua-language-support-<версия>.vsix` из [релизов](https://github.com/Lirniri/vscode-pluto-lua/releases) этого проекта.
2. Установите: `code --install-extension pluto-lua-language-support-<версия>.vsix`, или в VS Code откройте панель расширений, нажмите `...` и выберите **Install from VSIX...**. Если установлена старая копия с другим издателем, сначала удалите её.
3. Откройте файл `.pluto` (или `.lua`). Подсветка и языковые возможности работают сразу; откройте **папку** проекта, чтобы индекс видел все его файлы.
4. Нажмите `Ctrl+Shift+P` и выполните **Plua: Настройки**: панель настроек (вкладка для каждой группы, выбор цвета).
5. Откройте [demo-highlight.pluto](demo-highlight.pluto): все виды токенов грамматики в одном файле, чтобы настраивать на нём цвета.
6. По желанию: компилятор Pluto (`plutoc`) для диагностики на лету и интерпретатор Lua для проверки синтаксиса файлов `.lua`; оба находятся сами (см. разделы ниже).

Сам язык описан в [документации Pluto](https://plutolang.github.io/).

## Возможности в Visual Studio Code

Что в проекте есть, по группам. Большая часть работает в файлах `.pluto`, многое и в `.lua` (см. [Файлы Lua и индекс](#файлы-lua-и-индекс)).


### Подсветка и цвета

- **Свои цвета подсветки:** цвета и начертания для функций, параметров, типов, возвращаемых типов, ключевых слов, операторов, скобок таблиц по глубине вложенности и другого, с отдельным цветом для тёмных и светлых тем и выбором цвета в `settings.json`; неверные значения сообщаются и никогда не применяются. См. [Цвета подсветки](#цвета-подсветки).

### Автодополнение и навигация

- **Автодополнение** ключевых слов Pluto, стандартной библиотеки (`string.split`, `table.contains`, `io.listdir`, `json.encode` и других), встроенных модулей (`require "pluto:json"`) и всего, что объявлено в вашей рабочей области: классов, методов, полей, функций с параметрами и аннотациями типов, перечислений и идентификаторов модулей из манифестов `info.json`.
- **Подсказка при наведении** с сигнатурой, комментарием над объявлением, файлом, откуда оно взято, и для функций и методов их исходным кодом в сжатом виде (без комментариев, с нормализованными отступами, логические блоки разделены пустыми строками; см. `plua.hover.showFunctionBody` и `plua.hover.maxBodyLines`). Наведение на возвращаемый тип (`void` в `function f(): void`) показывает и то, что разработчик написал в комментарии `@return` над функцией или внутри неё, например `-- @return bool Удалось ли это`; те же строки входят в подсказку функции и в справку по сигнатуре.
- **Справка по сигнатуре** при вводе `(` с выделением текущего аргумента.
- **Переход к определению** (`F12` / `Ctrl+Click`) для классов, методов, функций, переменных и файла, на который указывает `require("...")`.
- **Структура файла и «хлебные крошки»**, **переход к символу в рабочей области** (`Ctrl+T`) и **сворачивание** блоков, комментариев и маркеров `--#region`.
- **Показать код:** ссылка **Показать код** внизу подсказки при наведении открывает объявление в широком встроенном окне (peek): слева код, справа список мест, даже если объявление всего одно.

### Типы и помощники при наборе

- **Аннотации типов:** ввод `:` в `function f(a: `, `function f(): ` или `local x: ` открывает список типов (встроенные типы и ваши классы, каждый ещё и как nullable `int?`); nullable-типы подсвечиваются и поясняются при наведении (`(допускающий nil) int? — Может быть int или nil`), в том числе в справке по сигнатуре. Понимаются оба написания, `int?` и `?int`.
- **Объединения типов** (`int|string`, `?int|string?`): наведите на `|`, чтобы увидеть, что может хранить всё объединение, с явным `nil`.
- **Значения параметров по умолчанию:** тип параметра без значения по умолчанию (`test: bool`) получает жёлтую волнистую линию с подсказкой, пока на нём курсор, а значения, подходящие типу (`= false`, `= true`), предлагаются в автодополнении, в том числе сами, если курсор постоял. См. [Значения параметров по умолчанию](#значения-параметров-по-умолчанию).
- **Подсказки для типов и `switch`:** серый `:` после имени параметра без типа или после `)` функции (`Tab` открывает список типов), значения, подходящие `return`, серые `break` / `case` / `default:` и `:` после `case`, жёлтые линии для недостающего и предупреждения о функции, которая возвращает не то, что обещает. См. [Помощники при наборе](#помощники-при-наборе).
- **Помощники при наборе:** новая строка после запятой в многострочном списке (после паузы, чтобы можно было продолжить печатать), серые подсказки, которые принимаются по `Tab` (`()` после `function`, ` = ` после `["key"]`, ` then` / ` do` после заголовка блока), предупреждение о параметре или ключе таблицы, написанном дважды, и быстрое исправление (или автоматическое после паузы) для закрывающей скобки, не подходящей к последней открытой (`{ ]`). См. [Помощники при наборе](#помощники-при-наборе).
- **Умные многострочные списки:** если у функции `(` ... `)` или у таблицы `{` ... `}` стоят на отдельных строках, первый элемент, набранный сразу после открывающей скобки, переносится на свою строку с отступом, а Enter в конце элемента добавляет недостающую запятую. См. [Многострочные параметры и таблицы](#многострочные-параметры-и-таблицы).
- **Автоматический `end`** при нажатии Enter после `function`, `if ... then`, `for ... do`, `while ... do`, `class`, `switch ... do` и т. д.
- **Исправление раскладки клавиатуры**: текст, набранный по ошибке в кириллической раскладке (`дщсфд`), превращается в английские клавиши с того же места (`local`) при наборе или в конце слова; `Э` / `э` сразу открывают строку, русский текст внутри остаётся. См. [Исправление раскладки клавиатуры](#исправление-раскладки-клавиатуры).
- **Умные отступы по Enter**: пустые строки внутри блоков сохраняют отступ (направляющие не рвутся), строка после `case ...:` получает отступ. См. [Автоотступы](#автоотступы).
- **`return` для функции с типом**: Enter после заголовка функции с типом возврата, отличным от `void` (`function is_alive(entity: int): bool`), оставляет пустую строку для курсора и ставит под ней строку `return `, перед добавленным `end` (`plua.format.autoReturn`). Если тип снова удалить, пустой `return` уходит вместе с ним (с короткой паузой, когда пропало `:`); `return` со значением остаётся, а серый текст в конце заголовка сообщает, что функция возвращает, что она делает и что тип данных не задан, с кодом при наведении и быстрым исправлением **Удалить возвращаемое?** (`plua.diagnostics.returnHint`).
- **Помощник по return** (`plua.returnHelper.*`, вкладка **Return**): пустой `return` удаляется, когда у его функции нет пригодного типа возврата (нет, стёрт или не тип, например `boo`), `return` со значением никогда; когда курсор стоит на пустой строке над `return `, созданным по Enter, пустая строка удаляется, а курсор переходит за `return ` (`idleDelayMs`, 2000 мс); а строка `#return = <выражение>` в теле функции по Enter или после паузы становится `return` в конце функции. Ctrl+Z отменяет каждое из этих действий.
- **Компиляторы**: список интерпретаторов и компиляторов (`plua.compilers.list`), которые проверяют файлы `.pluto` и `.lua`, с кнопками «Добавить» и «Удалить». См. [Компиляторы](#компиляторы).

Умные клавиши удаления (двойной Backspace / Delete на `end`, Shift + Backspace и Shift + Delete по кусочкам) и автоматический `end` работают и в файлах `.lua`, кроме того, что есть только в Pluto (`class`, `switch`, `try`, `enum`, `->`).

### Диагностика и проверки

- **Диагностика на лету** (волнистые линии и панель Problems):
  - ошибки и предупреждения компилятора Pluto, который проверяет код, не выполняя его (`plutoc -p -`; если есть только интерпретатор `pluto`, код компилируется через `load` и не вызывается);
  - встроенные проверки без компилятора: `require("...")` модуля, которого нет в рабочей области, вызовы с меньшим числом аргументов, чем у функции обязательных параметров (параметры с `?` или `= значение` необязательны), а в `info.json` ещё отсутствующий `id`, несуществующий файл `entry` и `dependencies` с неизвестными идентификаторами.

  Компилятор берётся из `plua.diagnostics.compilerPath`; если там пусто, то из рабочей области (`pluto/*/plutoc.exe`, `bin/pluto/*/plutoc.exe`, `tools/pluto/...`; побеждает новейшая версия, `plutoc` раньше `pluto`), затем из `PATH`. Если ничего не найдено, работают только встроенные проверки. Используемый компилятор записывается в канал вывода **Pluto**. В недоверенных рабочих областях компилятор не запускается.
- **Проверка синтаксиса Lua:** при включённой `plua.lua.enable` файлы `.lua` проверяются на синтаксические ошибки интерпретатором Lua (`luac`, `lua` или `luajit`), найденным в `bin/lua`, `tools/lua` и похожих папках рабочей области либо в `PATH`. Код только компилируется и никогда не запускается.
- **Пути к файлам в JSON:** путь вроде `"entry": "src/main.pluto"`, который указывает на несуществующий файл, получает предупреждение, а если файл просто переместили, то и быстрое исправление. См. [Проверка путей в JSON](#проверка-путей-в-json).

### Конфигурация

- **Панель настроек:** команда **Plua: Настройки** открывает окно с вкладками по группам настроек, с переключателями, списками выбора и настоящим выбором цвета. См. [Панель настроек](#панель-настроек).

### Файлы Lua и индекс

Языковые возможности работают и в файлах `.lua` (отключаются через `plua.lua.enable`, например при установленном `sumneko.lua`; проверка компилятором выполняется только для `.pluto`). Все файлы `.pluto` и `.lua` рабочей области индексируются в фоне и обновляются по мере правок. Файлы, попавшие под `.gitignore`, `.plutoignore` или настройки исключения ниже, в индекс не входят: они не показываются в автодополнении, подсказках и переходе к определению других файлов, а индекс подстраивается при изменении файла игнорирования. Открытый исключённый файл по-прежнему получает все возможности для собственного кода. Это лёгкий индекс, а не полноценный языковой сервер: типы выводятся только из аннотаций, `new Class(...)` и `require`.

### Сниппеты

| Префикс | Результат |
| --- | --- |
| `class`, `cls` | Класс с конструктором |
| `cls_ext` | Класс, наследующий другой класс |
| `fn`, `lfn`, `fnt`, `lambda` | Функция, локальная функция, функция с типами, лямбда |
| `switch` | Блок switch |
| `try` | `pcall` / `xpcall` (оператор try/catch удалён из Pluto) |
| `fori`, `forp`, `forip`, `fora` | Циклы: числовой, `pairs`, `ipairs`, for-as |
| `enum`, `req`, `pluto_use` | Перечисление, `require "pluto:..."`, `pluto_use "версия"` |

### Языки (английский и русский)

Сообщения расширения (подписи в подсказках и автодополнении, встроенная диагностика, тексты статуса и вывода) есть на английском и русском. По умолчанию `plua.language` равна `auto`: русский, если язык интерфейса редактора русский (`ru`, `ru-RU`), иначе английский. Значения `en` или `ru` закрепляют язык; он меняется на лету, перезагрузка не нужна. Названия и описания настроек и команд локализует сам VS Code через `package.nls.json` / `package.nls.ru.json`, и они следуют языку интерфейса (*Configure Display Language*). Тексты компилятора Pluto и документация встроенной библиотеки остаются на английском.

### Цвета подсветки

Расширение не меняет внешний вид вашей темы, пока вы это не включите. Установите `plua.highlight.applyColors` в `true` и опишите только те виды токенов, которые хотите перекрасить:

```jsonc
"plua.highlight.applyColors": true,
"plua.highlight.colors": {
    "functionName": { "color": "#FF8800", "fontStyle": "bold" },
    "parameter":    { "color": "#9CDCFE", "fontStyle": "italic" },
    "returnType":   { "color": "#4EC9B0" },
    "keyword":      "#C586C0"                   // короткая форма: цвет, затем при желании bold / italic / underline / strikethrough
},
"plua.highlight.tableBracketColors": ["#E6B450", "#59C2FF", "#AAD94C"]
```

Каждая запись это либо объект с `color` и `fontStyle`, либо короткая строка вроде `"#FF8800 bold"`. В `settings.json` у `color` объектной формы есть выбор цвета (нажмите на образец рядом со значением). `fontStyle` принимает `normal`, `bold`, `italic`, `bold italic`, `underline`, `bold underline`, `italic underline`. У цвета может быть прозрачность (`#FF880080`).

**Тёмные и светлые темы.** В объектной форме у каждого вида темы может быть свой цвет:

```jsonc
"returnType": { "color": "#4EC9B0", "lightColor": "#007A62" }
"functionName": { "darkColor": "#FFD866", "lightColor": "#8A6500" }
```

`color` действует в любой теме, `darkColor` переопределяет его в тёмных и высококонтрастных темах, `lightColor` в светлых и светлых высококонтрастных. Незаданный цвет заменяется на `color`; если для текущего вида темы цвета нет, остаётся цвет самой темы. У всех трёх есть выбор цвета, а цвета переключаются сами при смене темы. Та же объектная форма работает и в `plua.highlight.tableBracketColors`. Короткая строковая форма (`"#FF8800 bold"`) задаёт один цвет на все темы.

Неверное значение никогда не применяется: цвет вашей темы остаётся, а расширение показывает предупреждение с названием настройки и значением и кнопкой, которая открывает `settings.json`. Это относится к значению, которое не цвет и не стиль (`"blue"`, опечатка в `fontStyle`), полностью прозрачному цвету (`#0000`, `#00000000`), из-за которого текст стал бы невидимым, и неизвестному ключу (`"functonName"`). Пустая строка `""` просто означает «не задано».

| Ключ | Что красится |
| --- | --- |
| `functionName` | Имена объявляемых функций и методов, в том числе с длинными путями (`function api.handlers.add`). |
| `functionKeyword` | Ключевое слово `function` и `->` у лямбд. |
| `parameter` | Параметры функций и лямбд (`\|x: int\| -> int { ... }`). |
| `type` | Типы в аннотациях: `int`, `string`, `Vehicle`, `int?`, `int\|string`, в параметрах и переменных. |
| `returnType` | Только тип, который возвращает функция или лямбда: `void` в `function f(): void`, `int` в `\|x: int\| -> int { ... }`. Типы в параметрах сохраняют цвет `type`. |
| `typeColon` | Двоеточие перед типом в аннотации. |
| `keyword` | `if`, `then`, `end`, `return`, `for` и др. |
| `operator` | `=`, `+`, `and`, `?`, `??` и др. |
| `constant` | `true`, `false`, `nil`. |
| `modifier` | `local`, `public`, `private`, `static` и др. |
| `accessor` | Точка между именами, как в `a.b.c`. |

`plua.highlight.tableBracketColors` красит скобки `{ }` вложенных таблиц по глубине: первая запись для внешней таблицы, следующая для вложенной в неё и так далее. Список короче глубины повторяется, различаются до 8 уровней. Записи пишутся как выше, например `[{ "color": "#E6B450", "fontStyle": "bold" }, "#59C2FF"]`.

Расширение хранит эти цвета как правила `Pluto: ...` в `editor.tokenColorCustomizations` ваших пользовательских настроек. Ваши собственные правила там не трогаются, а выключение `plua.highlight.applyColors` удаляет наши. Правила подходят только к областям Pluto (`....pluto`), поэтому другие языки не затрагиваются.

В репозитории есть [demo-highlight.pluto](demo-highlight.pluto): файл со всеми видами токенов, чтобы смотреть на них при настройке цветов. У nullable-типов (`int?`) свои настройки, `plua.highlight.nullableTypeColor` и `plua.highlight.nullableTypeLightColor`, потому что они красятся поверх темы.

### Проверка путей в JSON

Строки в JSON-файле, похожие на путь к файлу, проверяются. По умолчанию это делается для манифестов модулей (`info.json`) и только для файлов `.pluto` и `.lua`, поэтому в других JSON ничего неожиданного не появляется. Строка считается путём, если оканчивается одним из расширений, не является URL или шаблоном (`*`, `{}`) и не является обычной фразой.

```jsonc
{
    "id": "garage",
    "entry": "main.pluto",
    "helper": "old/util.lua"          // предупреждение: File 'old/util.lua' not found. Did you mean '../lib/util.lua'?
}
```

- **Где ищется:** путь верный, если файл есть рядом с JSON-файлом или относительно папки рабочей области (или путь абсолютный). Файлы, исключённые через `.gitignore`, `.plutoignore`, `.luaignore` или `files.exclude`, всё равно считаются существующими, если лежат на диске.
- **Перемещённые файлы:** если файла нет, но файл с таким именем есть в другом месте проекта, предупреждение называет его, а быстрое исправление (`Ctrl+.`) заменяет путь на путь относительно JSON-файла. Первыми идут ближайший файл и тот, у которого путь заканчивается так же, как написанный.
- **Какие JSON-файлы:** `plua.json.files` это список шаблонов glob относительно папки рабочей области, например `["**/info.json", "config/*.json"]`, или `["**/*.json"]` для всех. `id`, `entry`/`main` и `dependencies` манифеста модуля (`info.json`) проверяются всегда.
- **Другие файлы:** `plua.json.extensions` перечисляет проверяемые расширения. С `plua.json.checkAllPaths` проверяется и каждое расширение, найденное среди файлов папки проекта (`.png`, `.txt`, ...); для этого один раз читаются имена всех файлов, без игнорируемых.
- **Папка не открыта:** без папки проекта (одиночный JSON-файл) ищется только рядом с файлом на диске, подсказок «возможно, вы имели в виду» нет. Расширение сообщает об этом один раз за окно уведомлением (отключается через `plua.json.notifyNoFolder`).

### Файлы игнорирования

Файлы, подходящие под `.gitignore`, `.plutoignore` или `.luaignore` (все в корне рабочей области, синтаксис `.gitignore`; список задаёт `plua.workspace.ignoreFiles`), не индексируются, поэтому для них нет автодополнения и навигации. `plua.workspace.exclude` добавляет шаблоны glob, а `files.exclude` и `search.exclude` тоже действуют.

Пока включена `plua.lua.enable`, файлы `.lua` проверяются на синтаксические ошибки интерпретатором Lua так же, как `plutoc` проверяет файлы `.pluto`. Интерпретатор: первая запись Lua из `plua.compilers.list`, иначе `plua.lua.compilerPath`, иначе `luac`, `lua` или `luajit` в `bin/lua`, `tools/lua`, `lua5.4` и похожих папках рабочей области (`luac`, который только разбирает код, предпочтительнее; побеждает новейшая версия), иначе `PATH`. С `lua` или `luajit` код компилируется через `load` и никогда не запускается. Чтобы программа из рабочей области была запущена, рабочая область должна быть доверенной. Отключается через `plua.lua.checkSyntax`.

### Многострочные параметры и таблицы

Для файлов `.pluto` и `.lua` (файлов Lua, пока включена `plua.lua.enable`). Работает только со списком, уже записанным на нескольких строках, то есть когда закрывающая `)` или `}` стоит на отдельной строке ниже открывающей. Для однострочных списков ничего не делает.

**Первый элемент переносится на свою строку.** Если вы начинаете набирать первый параметр или поле сразу после открывающей скобки, оно переносится на следующую строку с отступом на уровень глубже строки со скобкой:

```pluto
function name(test: bool = false      -- набрано на строке с `(`, `)` на строке ниже
)

-- становится
function name(
    test: bool = false
)

local cfg = { enabled = true          -- то же для таблиц
}

-- становится
local cfg = {
    enabled = true
}
```

**Enter добавляет запятую.** Нажмите Enter в конце параметра или поля внутри такого списка, и недостающая запятая ставится в его конец (перед `-- комментарием`, если он есть), а курсор переходит на новую строку с тем же отступом. Уже стоящая запятая (или `;` в таблице) не дублируется, а Enter на пустой строке просто переносит строку:

```pluto
function name(
    test: bool = false|          -- Enter
)

-- становится
function name(
    test: bool = false,
    |
)
```

Код при этом старается не ломать: строки и комментарии пропускаются; вложенные таблицы и списки обрабатываются каждый на своём уровне; строка, оканчивающаяся открывающей скобкой или незавершённым выражением (`a = 1 +`), запятую не получает; `...` остаётся последним параметром без запятой; операторы внутри функции в таблице, тело лямбды (`-> int { ... }`) и аргументы вызова не затрагиваются; автоматический `end` продолжает работать. Оба режима отключаются: `plua.format.multilineParams` для списков параметров и `plua.format.multilineTables` для таблиц.

### Значения параметров по умолчанию

Пока вы пишете параметры объявления функции в файле Pluto, параметр, у которого есть тип, но нет значения по умолчанию, помечается, а значения, подходящие его типу, предлагаются.

```pluto
function name(test: bool|)          -- курсор сразу после типа
```

- **Жёлтая линия.** Тип (`bool`) получает жёлтую волнистую линию, пока курсор на параметре; наведите на неё, чтобы увидеть подсказку вроде ``` У `test` нет значения по умолчанию. Можно задать `= false`, `= true`. ``` Линия пропадает, когда курсор уходит с параметра или ставится запятая. Она не показывается у параметра, у которого уже есть `= значение`, у параметра без типа и у типа, который ещё набирается (`bo`). Это подсказка редактора, а не сообщение в панели Problems. Отключается через `plua.highlight.paramNoDefault`; цвета задают `plua.highlight.paramNoDefaultColor` и `plua.highlight.paramNoDefaultLightColor`.
- **Значения по типу.** Когда курсор сразу после типа (или после пробела за ним), список подсказок начинается с подходящих значений, которые вставляются как ` = значение`:

  | Тип | Предлагается |
  | --- | --- |
  | `bool` | `= false`, `= true` |
  | `int` | `= 0`, `= 1`, `= -1` |
  | `float` | `= 0.0`, `= 1.0`, `= -1.0` |
  | `number` | `= 0`, `= 1`, `= -1` |
  | `string` | `= ""` |
  | `table`, `{ x: int }` | `= {}` |
  | `function` | `= function() end` |
  | `any` | `= nil`, `= false`, `= 0`, `= ""`, `= {}` |
  | класс (`Vehicle`) | `= new Vehicle()` |
  | `int?`, `?string`, ... | значения типа, затем `= nil` |
  | `int\|string` | значения каждого члена |

  Типы остаются в списке после них (`bool` ещё может стать `boolean`). Нажмите `Ctrl+Space`, чтобы открыть список самому.
- **Само.** Если курсор постоял сразу после типа `plua.completion.defaultValuesDelayMs` (800 мс), список открывается без нажатия клавиш. Перемещение курсора или набор текста запускает ожидание заново, а для одного и того же места список повторно не открывается. Задержка `0` отключает это, а `plua.completion.defaultValues` в `false` отключает значения совсем.

### Помощники при наборе

Небольшие помощники во время набора для файлов `.pluto` и, где это уместно, `.lua` (пока включена `plua.lua.enable`). У каждого своя настройка.

**Новая строка после запятой.** В многострочном списке параметров или таблице (закрывающая `)` или `}` стоит на отдельной строке ниже) запятая, набранная в конце элемента, начинает новую строку с отступом элементов, как `end` появляется после Enter. Новая строка появляется после короткой паузы (`plua.format.newLineAfterCommaDelayMs`, 700 мс): если вы продолжили печатать или сдвинули курсор, её не будет, поэтому `test: bool = false, test1` может остаться в одной строке. Однострочные списки, вызовы и строка, под которой уже есть пустая строка, не затрагиваются.

```pluto
function name(
    test: bool = false,|          -- остановитесь на секунду после запятой
)

-- становится
function name(
    test: bool = false,
    |
)
```

**Подсказки серым.** Текст, который мог бы идти дальше, показывается серым после курсора, а `Tab` принимает его (это подсказки в строке самого VS Code, `editor.inlineSuggest.enabled`):

| Что набрано (`▮` это курсор) | Серая подсказка | После `Tab` | Настройка |
| --- | --- | --- | --- |
| `function▮`, `function name▮`, `local f = function▮` | `()` | `function(▮)`, курсор между скобками | `plua.format.suggestParens` |
| `["key"]▮` в начале поля таблицы | ` = ` | `["key"] = ▮` | `plua.format.suggestTableKeyAssign` |
| `if x▮`, `elseif a and b▮` | ` then` | `if x then▮` (Enter затем добавит `end`) | `plua.format.suggestBlockWords` |
| `while x▮`, `for i = 1, 3▮`, `for k, v in pairs(t)▮` | ` do` | `... do▮` | `plua.format.suggestBlockWords` |

Ничего не предлагается, если текст уже есть (`function name(`), если заголовок не закончен (`if a and`), в строках и комментариях, для типа (`x: function`), а также для `local function` / `public function`, пока нет имени. Если подсказки в строке отключены, `()` предлагается пунктом списка автодополнения.

**then или do после `if`.** Pluto принимает и `if x then`, и `if x do` (`while` и `for` принимают только `do`). `plua.format.ifBlockWord` выбирает, что предлагать: `then`, `do`, `off` или `auto` (по умолчанию): считаются заголовки `if` / `elseif` текущего файла и берётся тот вариант, которого больше; если в файле поровну, решает остальная рабочая область (неигнорируемые файлы, читаются один раз и хранятся несколько секунд), а если ориентироваться не на что, берётся `then`.

**Циклы.** Пока пишется заголовок `for`, подсказки идут вместе с ним (`Tab` принимает первую, `Alt+]` показывает следующую):

| Что набрано (`▮` это курсор) | Предлагается |
| --- | --- |
| `for▮` | `i = 1, 10`, `i, v in ipairs(t)`, `k, v in pairs(t)`, `t as v`, с местами для заполнения |
| `for k, v in▮` | `ipairs(t)`, `pairs(t)`, `next, t` |
| `for i = 1,▮` | `#items`, длина ближайшей таблицы выше |
| `for i = 1, 10,▮` | шаг: `1`, `2` или `-1`, `-2`, когда начало больше конца |

Ближайшая таблица файла (`local items = { ... }`) даёт имя, а её вид решает, что идёт первым: для массива `ipairs`, для полей `pairs`. `plua.format.nameStyle` выбирает `short` слова (`i`, `k`, `v`, `t`) или `full` (`index`, `key`, `value`, `table_name`), а `plua.format.names` задаёт ваши слова для любого из них, например `{ "value": "item" }`. Всё это включает `plua.format.suggestFor`; готовые сниппеты не затрагиваются.

**Что пробегает числовой цикл.** Наведите на `for` цикла с числами, чтобы увидеть значения: `for i = 1, 10, 2` покажет, что `i` принимает значения 1, 3, 5, 7, 9 (5 раз, шаг 2). Подсказка сообщает, когда цикл не выполнится (`for i = 5, 1`), когда шаг равен 0, а для `for i = 1, 3, 5`, что шаг больше расстояния и цикл выполнится один раз. Отключается через `plua.hover.forPreview`.

**Типы параметров и возвращаемых значений.** Параметр, написанный без типа (`value2`), получает жёлтую линию под именем, пока на нём курсор, а после паузы (`plua.format.suggestParamTypeDelayMs`, 600 мс) рядом серый `:`. `Tab` вставляет `: ` и открывает список типов; когда тип готов, подхватывают подсказки значения по умолчанию (`= false`). Серое двоеточие не показывается, пока открыт список автодополнения: оно появится, когда вы закроете этот список (`Esc` или выбор), сколько бы это ни длилось. `Esc` на серой подсказке скрывает её до следующего ввода или перемещения курсора. Такой же серый `: ` появляется после `)` функции без возвращаемого типа. После `return ` в функции с возвращаемым типом (`function f(): bool`) предлагаются подходящие значения (`true`, `false`; `0`, `1`, `nil` и т. д. по типу). Поля класса тип не просят: `public name` в Pluto допустимо. `void`, `any` и nullable-типы возврата `return` не требуют.

**switch и case.** Внутри `switch`:

| Где | Предлагается | Настройка |
| --- | --- | --- |
| после значений `case`: `case 1▮`, `case 2, 3▮` (после паузы) | `:` | `plua.format.suggestCaseColon` |
| пустая строка в теле `case`, которое ничем не завершено (не `default`), перед следующим `case`, `default` или `end` | `break` | `plua.format.suggestCaseBreak` |
| пустая строка на уровне `case` | `case ` и `default:` (`default` только один раз) | `plua.format.suggestCaseWords` |
| пустая строка в теле класса без `__construct` или `function▮` там | `function __construct()` / ` __construct()`; при `extends` второй вариант (`Alt+]`) ещё и вызывает `parent:__construct()` | `plua.format.suggestConstructor` |

`case` без `:` получает жёлтую линию под словом `case`, пока курсор на его строке (`plua.highlight.caseNoColon`). `plua.diagnostics.caseFallthrough` может отмечать подсказкой `case`, который ничем не завершён (`break`, `return`, `goto`, `continue`, `error(...)`) и переходит в следующий; `case` с пустым телом, который даёт двум `case` одно тело, не трогается. Компилятор Pluto предупреждает о том же.

**Функция, которая возвращает не то, что обещает.** Функция с возвращаемым типом (`function f(): int`), которая нигде не использует `return`, получает предупреждение на типе, а функция `void`, возвращающая значение, на `return` (`plua.diagnostics.returnTypes`: `warning`, `error` или `off`). Функция, которая вызывает ошибку, nullable-тип, `any` и функция без тела не трогаются.

**Имена, написанные дважды.** Параметр с тем же именем, что у предыдущего параметра функции или лямбды (`function f(a, a)`, `|x, x| -> x`), и ключ, заданный дважды в одной таблице (`{ a = 1, a = 2 }`, а также `a` и `["a"]`), получают предупреждение на втором. Чтобы изменить это, задайте `plua.diagnostics.duplicateParams` в `error` или `off`.

**Не подходящая закрывающая скобка.** Если вы набрали `]` там, где последняя открытая скобка `{`, и никакая другая открытая скобка `]` не принимает, она подчёркивается с текстом `Ожидалась '}', чтобы закрыть скобку, открытую на строке N`, а быстрое исправление (`Ctrl+.`) заменяет её. Что делать, выбирает `plua.format.fixMismatchedBrackets`: `off` игнорирует её, `suggest` (по умолчанию) подчёркивает и предлагает исправление, `auto` ещё и заменяет её сама, когда вы перестали печатать на `plua.format.fixMismatchedBracketsDelayMs` (1200 мс). Набор текста или перемещение курсора за это время отменяют замену, а сама замена это один шаг в истории отмены. Забытая закрывающая скобка (`{ a[1 }`), лишняя и скобки в строках и комментариях не затрагиваются.

### Компиляторы

Вкладка **Компиляторы** панели настроек (и `plua.compilers.list`) хранит список программ, которые проверяют код, не запуская его. Запись — это язык (`pluto` или `lua`) и путь: полный путь или имя команды из `PATH` (работают `${userHome}` и `${env:NAME}`). **Добавить** создаёт новую строку, **x** удаляет. Для каждого языка берётся первая запись, указывающая на исполняемый файл; если таких нет, действуют `plua.diagnostics.compilerPath` / `plua.lua.compilerPath`, а затем автоматический поиск, как раньше. Список — настройка уровня машины, поэтому рабочая область не может выбрать, какая программа запустится; в пути нельзя управляющие символы, кавычки и `< > | & ;`; в недоверенных рабочих областях ничего не запускается.

### Исправление раскладки клавиатуры

Набрали `дщсфд ы = ЭПриветЭ` с включённой русской раскладкой? Получится `local s = "Привет"`: кириллические клавиши заменяются английскими с того же места, только в коде (не в комментариях и не в строках), а клавиша `Э` (`э`) открывает строку с `"` (`'`), поэтому текст внутри остаётся русским. `Э` / `э` снова закрывают строку (но не пустую, так что текст может начинаться с `Э`).

- `plua.layoutFixer.mode`: `live` преобразует каждую клавишу сразу; `allCodeWords` преобразует слово, когда его завершает пробел или знак; `keywordsOnly` только слова, дающие ключевое слово (`local`, `function`, `end`...); во всех клавиша кавычки сразу открывает строку. `off` оставляет только команду **Plua: Преобразовать раскладку клавиатуры**, которая преобразует выделение или текущую строку (и знаки `.` `,` `;` `:` `?` `№` русской раскладки рядом с кириллическими буквами).
- `plua.layoutFixer.baseKeyboardProfile`: `physicalQwerty` преобразует буквы, кавычки, скобки, `;` `:` `,` `.` и обратную кавычку (`х` -> `[`, `б` -> `,`, `ю` -> `.`); `hybridSmart` буквы, кавычки, скобки и `;` `:`; `keepLocalPunctuation` только буквы и кавычки.
- `plua.layoutFixer.sourceLayouts`: `ru`, `uk` (`і ї є ґ`), `be` (`ў і`). `plua.layoutFixer.customMap` добавляет собственные замены.
- `.` или `,`, набранные в русской раскладке, нельзя отличить от английских, поэтому эти знаки при наборе не меняются.
- Ctrl+Z откатывает набранную клавишу и её преобразование вместе; отмена и повтор заново не преобразуются.

### Автоотступы

Пустая строка внутри блока теряет отступ, когда вы с неё уходите (`editor.trimAutoWhitespace`), и направляющая отступа рвётся. С `plua.autoIndent.preserveEmptyLines` нажатие Enter на пустой строке внутри блока даёт и оставленной строке, и новой отступ блока: как у последней строки с кодом выше, на уровень глубже после `do`, `then`, `else`, `repeat`, `function(...)`, `case ...:`, `default:`, `class`, `try` или открытой `{`, `[`, `(`. Размер уровня (табуляция или пробелы) берётся из редактора (`editor.insertSpaces`, `editor.tabSize`). `plua.autoIndent.indentAfterCase` выбирает, делать ли отступ после `case ...:` и `default:`; `plua.autoIndent.trimOnSave` убирает пробелы на пустых строках при сохранении файла. Ctrl+Z откатывает Enter вместе с отступом.

### Живые директивы

Строка, начинающаяся с `#`, работает с переменной, параметром, полем или `return` функции вокруг. Это временная строка редактора (она не является допустимым кодом, поэтому исчезает, когда сделала своё дело), а та же строка после `--` — постоянная заметка, которая остаётся в коде.

| Строка | Что делает |
| --- | --- |
| `#speed = 2.5` | По Enter находит ближайший `speed` выше (объявление, присваивание или параметр, например `function f(speed = 1)`) и подставляет новое значение; строка директивы удаляется. Поле работает так же: `#self.hp = 100`. |
| `#return = self.hp > 0` | Делает `return` в конце функции или заменяет последний (также после паузы). |
| `#speed >show_up` | Показывает ближайшее объявление, присваивание или `return` для `speed` **выше** со значением, типом и строкой. Enter или Esc удаляет строку. |
| `#speed >show_down` | Показывает ближайшее изменение, использование или финальный `return` **ниже**. |
| `#acc >show_all` | Все места `acc` в её функции: объявление, присваивания, чтения, return, со ссылками при наведении. |
| `#acc >type` | Выведенный тип и откуда он взят; `#return >type` даёт объединение типов всех return (`bool\|string`). |
| `#return >sign` | По Enter вписывает тип возврата в заголовок (`function f(a): bool`). `#acc >sign` вписывает его при объявлении (`local acc: int = 2`). |
| `#acc >trace` | Как получено значение, до 3 шагов вверх, код каждого шага при наведении. |
| `#acc >rename = total` | По Enter переименовывает переменную в её функции (`#self.hp >rename = health` во всём файле); строки, комментарии и поля других объектов (`obj.acc`) не трогаются. |
| `#acc >const` | По Enter дописывает `<const>`, если `acc` больше нигде не присваивается. |
| `#acc >unused` | Отмечает переменную, которая после объявления не читается; быстрое исправление удаляет объявление. |
| `#move >calls` | Вызовы функции в файле с указанием класса и метода, в которых они стоят. |
| `-- #speed >show_up` | То же в комментарии: остаётся в коде, а серый текст следует за каждым изменением файла. |

Серый текст в конце строки говорит, что произойдёт или что найдено (`выше: local speed = 1.0 (стр. 12, тип float)`, `заменит стр. 12 на: local speed = 2.5`), обрезается по `plua.liveDirectives.maxPreviewLength`; во всплывающей подсказке код вокруг места (`maxContextLines` строк) и ссылка на строку. Поиск идёт не дальше `maxSearchDistance` строк. После `#` автодополнение предлагает `return`, параметры, локальные переменные и поля `self.` в зоне досягаемости; после `#speed >` предлагает `show_up` и `show_down`. Ctrl+Z отменяет изменение по строке `=` за один шаг.

`#` и `>` можно заменить (`plua.liveDirectives.prefix`, `commandSeparator`), а у команд могут быть другие имена (`commandAliases`), всё это сразу, без перезапуска. Константа (`<const>`) не меняется, пока не выключена `skipConst`; `allowModify` выключает изменение, `ignoredTargets` перечисляет имена, которые не трогать. Пока открыт список подсказок или подсказки параметров, таймер курсора, стоящего на пустой строке над `return`, не идёт и снова запускается, когда они закрыты.

### Панель настроек

Запустите **Plua: Настройки** из палитры команд (`Ctrl+Shift+P`), чтобы открыть окно, сделанное для этого расширения. В нём **вкладка для каждой группы**: Общие, Индекс и игнор, Компиляторы, Return, Живые директивы, Автоотступы, Раскладка, Автодополнение, Подсказки при наведении, Структура файла, Диагностика, Подсветка и цвета, Помощники при наборе и Пути в JSON. У каждой настройки свой текст, подходящий ей элемент (переключатель, список выбора, число, текст, список с отдельной строкой на запись), ссылка **Сбросить** и отметка слева, если значение отличается от значения по умолчанию. Для цветов есть настоящий **выбор цвета**: цвета подсветки это таблица со строкой для каждого вида токенов (цвет, тёмная тема, светлая тема, стиль), а цвета скобок таблиц это список, в который можно добавлять и из которого можно удалять. Есть поиск, который смотрит во всех вкладках.

Панель читает и пишет те же настройки, что обычный редактор настроек и `settings.json`: изменение сразу сохраняется в пользовательских настройках, значение по умолчанию убирается из `settings.json`, а не записывается туда, а то, что вы поменяли в `settings.json`, появляется в панели. Недопустимое значение (не цвет вместо цвета, число вне диапазона) отклоняется с причиной, а элемент показывает значение, действующее сейчас. Менять через неё можно только настройки этого расширения.

- **Plua: Проверить скрипт** — проверяет текущий файл через `plutoc -p`.
- **Plua: Перестроить индекс рабочей области**

В Sublime Text выберите **Preferences > Browse Packages...**, чтобы открыть папку «Packages» вашей установки ST.

Откройте консоль в этой папке и выполните команду:

```
git clone https://github.com/PlutoLang/Syntax-Highlighting "Pluto Syntax Highlighting"
```

После этого «Pluto» появится среди вариантов подсветки синтаксиса в Sublime Text.

### Visual Studio Code

Расширение написано на обычном JavaScript и не требует сборки.
